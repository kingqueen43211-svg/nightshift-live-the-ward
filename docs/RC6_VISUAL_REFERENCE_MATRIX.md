# RC6 visual reference reconciliation

## Purpose

This matrix converts the ten recovered ChatGPT concept frames into testable implementation guidance. The PNGs live in `art-source/references/` with their original filenames so a reviewer can compare intent and implementation without shipping baked mock UI, invented viewer counts, or concept-only state in `dist/`.

These images are references, not proof. Acceptance still requires current 1280×720 and 1920×1080 captures from the running build. A reference is not copied full-screen into the product; each row identifies the world layer, interaction, or hierarchy that must be rebuilt as real state-driven UI and scene choreography.

## Comparison capture checklist

For each implemented row:

1. Capture the current build at 1280×720 and 1920×1080 with the exact room, camera node, and engine state recorded.
2. Pair the product capture with the reference filename and annotate what was intentionally preserved, changed, or rejected.
3. Verify that simulation/live source labels, votes, inventory, health, danger, power, and ending provenance come from real state rather than baked art.
4. Run reduced motion, low effects, high contrast, caption customization, and compact HUD variants where the row depends on them.
5. Keep human newcomer comprehension, audible mix quality, native OBS alpha/audio routing, real Twitch, and subjective cinematic quality marked as external evidence until independently observed.

## Source-only inventory rule

`art-source/references/` is excluded from the deployable `dist/` product. If a future implementation derives a production asset from a reference, record the new original filename, prompt or editing constraints, derivative path, dimensions, compression comparison, and visual QA evidence in the asset provenance documentation. Never promote a concept frame containing fake UI or metrics as a playable scene.
